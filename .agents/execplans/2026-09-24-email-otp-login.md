# ExecPlan: passwordless email-code sign-in

Living document (contract: `.agents/PLANS.md`). Branch: `feat/platform`. Start: `321fb3c`.

## Purpose

Owner request (2026-09-24): platform sign-in by one-time email code, sent with Cloudflare
Email Sending from a webforai.dev address; explain how to enable GitHub login; list what is
missing before promoting the platform publicly.

Outcome: `/login` and `/signup` become one flow — enter email → receive a 6-digit code from
`login@webforai.dev` ("webforai platform") → enter it → signed in (account created on first
sign-in). Passwords are no longer accepted in production. The GitHub button appears only when
the deployment has GitHub credentials.

## Design

- Better Auth `emailOTP` plugin (intended model; uses the existing `verification` table):
  6 digits, 10-minute expiry, 3 attempts per code, codes stored hashed, sign-up on first
  sign-in allowed. `sendVerificationOTP` sends through the Workers `send_email` binding
  `EMAIL`, restricted by `allowed_sender_addresses` to `login@webforai.dev`, awaited so a send
  failure reaches the user.
- Rate limiting: Better Auth's limiter with `storage: "database"` (new `rateLimit` table,
  generated by the Better Auth CLI, migrated by drizzle-kit), explicitly enabled (its
  production auto-detect does not apply on Workers), client IP from `cf-connecting-ip`.
  1.6.26's database storage retries a lost first-insert race and increments conditionally,
  so parallel isolates are safe. The plugin's own send limit (3 per 60 s) applies on top.
- Passwords: `emailAndPassword` only when `AUTH_PASSWORD_LOGIN=true` (local/e2e dev vars);
  never set in production.
- `GET /api/auth-methods` (public) → `{ github: boolean }` for the sign-in page.
- Sender domain: `wrangler email sending enable webforai.dev` (adds SPF/DKIM; the zone had no
  mail records). DMARC is left to the owner (dashboard DNS).

## Surprises & discoveries

- The Better Auth CLI is now the npm package `auth` (the repo's `pnpm exec auth` assumed a
  local install that no longer exists); `npx auth@<exact better-auth version>` regenerates.
- Better Auth 1.6.26's database rate-limit storage already retries a lost first-insert race
  and increments conditionally, so no custom storage was needed on Workers.

- [x] (2026-09-24) Follow-ups after the owner's first real sign-in:
      - Code "009782" failed: it came from the test email sent at 16:02; the owner's own
        request at 16:14 rotated the code (hash of 009782 ≠ stored hash). Fix: encrypted
        storage + `resendStrategy: "reuse"` so every email within the window has the same
        code (6a97a9b, deployed 8bac2670).
      - GitHub `account_not_linked`: the pre-existing password account had an unverified
        email; Better Auth's `requireLocalEmailVerified` (kept) refuses to link. One
        email-code sign-in verifies it. OAuth errors now land on `/login?error=` with an
        explanation (6a97a9b).
      - Turnstile (captcha plugin) wired, inactive until keys are set.
      - Launch items (not yet deployed): account deletion, legal pages, OG image,
        robots.txt, opt-in `respectRobotsTxt` (8f42fe2, 02d0bb8, 0291c88).
