## Purpose / Big Picture

Owner request (2026-09-24): "improve API Cost" on platform.webforai.dev, clarified as three
outcomes:

1. **Price level** — revisit $/credit, the free allowance and per-engine credits against
   competitors and our own unit costs. Changes the credit schedule
   (`src/billing/credits.ts`), Stripe tiers (`scripts/stripe-setup.ts`), `04_billing.md`.
   Numbers are an owner decision: proposed with evidence, implemented after approval.
2. **Presentation** — the landing states prices in credits only; visitors must do the
   arithmetic. Show dollars per 1,000 pages per engine, what the free tier buys, and a
   small monthly estimate.
3. **Cost of goods** — lower our Cloudflare/proxy cost per successful page without changing
   results or prices.

Out of scope: running `stripe:setup` against the live Stripe account or deploying — the
owner does both.

## Decision log

- (2026-09-24) **Price level — option A, owner-approved.** Credits: fetch 1, browser 5→2,
  proxy-fetch 2, proxy-browser 5→10; screenshot/rehost unchanged. Free allowance 500→1,000
  credits/month. Graduated Stripe tiers per credit: 1–1,000 $0; 1,001–100,000 $0.001;
  100,001–1,000,000 $0.0007; above $0.0005 (was: first 500 $0, then $0.002).
  Per 1k pages at the first paid tier: fetch $1, browser $2, proxy-fetch $2, proxy-browser
  $10, auto (~20% escalation) ~$1.2.
  Evidence (read 2026-09-24): Firecrawl $1–3.80/1k flat, ZenRows JS $1.65, ScraperAPI JS
  $1.49, ScrapingBee JS $0.99 at 100k/month; our old static $2 / JS $10 were 2–10x.
  Estimated COGS per 1k: fetch ~$0.01, browser ~$0.25, proxy-fetch ~$0.45, proxy-browser
  ~$10 at $4/GB residential with no request blocking (below the old 5-credit price) —
  hence proxy-browser goes up while everything else goes down.
- (2026-09-24) Cost-of-goods scope for this plan: single navigation in both browser engines;
  block images/media/fonts when no screenshot is requested; no Workflow retries for pages
  where every tier already failed; short Cache API cache for the public demo; index for the
  usage-report cron. Deferred (measure first / larger): Browser Rendering session reuse,
  container Chromium reuse + instance spreading + sleepAfter, auto escalation tuning,
  paid-result caching, job KV/R2 I/O cleanup.

## Surprises & discoveries

- Local Chromium measurement (no proxy, 2026-09-24), old "networkidle, else navigate again"
  vs new single navigation + image/media/font blocking: Markdown identical on 5/6 pages
  (Wikipedia, GitHub, Vite, MDN, Zenn); BBC News never goes idle and differs slightly (live
  content). Time −10–50%. Bytes −1% (GitHub, JS-heavy) to −46% (BBC, which also dropped the
  second navigation); Wikipedia −8%, Vite −25%, MDN −37%. JavaScript, not images, dominates
  page weight, so the audit's 40–70% bandwidth estimate was optimistic: proxy-browser COGS
  after this change is more like $5–9 per 1k pages at $4/GB, not ~$4.
